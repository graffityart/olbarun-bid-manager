# 올바른 입찰관리 (개인용)

Next.js + Vercel + Neon Postgres 기반 네이버 파워링크 입찰 관리 도구입니다.

## 현재 지원
키워드 동기화, 목표 순위별 평균 입찰가 조회, 최소/최대 입찰 한도, 변경 미리보기, 선택 키워드 수동 적용, 변경 이력, CSV 내보내기.
샘플 데이터는 실제 네이버 데이터가 아닙니다. VPS 작업기와 연결하면 순위 조회와 목표 순위 자동입찰을 실행할 수 있습니다.

## 설치 및 배포
1. 비공개 GitHub 저장소에 이 폴더의 내용을 업로드합니다.
2. Vercel에서 저장소를 Import합니다. Framework Preset은 Next.js입니다.
3. Neon에 전용 DB를 생성합니다. `.env.example`의 환경변수를 Vercel의 Production/Preview에 설정합니다.
4. `APP_PASSWORD`는 16자 이상으로 설정합니다. 설정되지 않으면 접근이 차단됩니다.
5. 직접 연결 문자열을 `DATABASE_URL_UNPOOLED`로 설정하고 `npm run db:migrate`를 한 번 실행합니다. 기존 사이트 DB를 쓰지 않는 것이 권장됩니다.
6. `npm run build` 후 배포합니다. DB 마이그레이션은 빌드 과정에서 자동 실행되지 않습니다.
7. 로그인 후 네이버 연결 → 실제 키워드 동기화를 실행합니다. 실제 적용 전 소수 키워드로 검증합니다.

`NAVER_CUSTOMER_ID`는 Customer ID, `NAVER_API_KEY`는 액세스 라이선스, `NAVER_SECRET_KEY`는 비밀키입니다. 키와 비밀번호를 GitHub에 올리지 마세요.

## 검증
`npm run check`, `npm test`, `npm run build`
실제 네이버 API 검증은 광고계정 연결 후 필요합니다. 평균 입찰가는 순위를 보장하지 않습니다.
현재 순위는 VPS의 검색 결과 관측값이며 모든 사용자에게 동일한 순위를 보장하지 않습니다.
Vercel Hobby에서 분 단위 상시 작업을 전제로 하지 않습니다. 상시 자동입찰에는 아래 VPS 서비스를 사용합니다.

## VPS 자동입찰
`scripts/bid-worker.mjs`는 관리 화면의 실행 요청을 DB에서 가져오는 상시 서비스입니다. 선택 키워드 전체 조회 → 확인된 목표 밖 순위만 순차 +10원 → 마지막 증액 후 대기 → 다음 회차를 실행합니다. 기본 대기 180초는 운영 설정이며 네이버 반영 시간을 보장하지 않습니다. 미노출/조회 불확실은 증액하지 않습니다. 증액 대상이 없으면 완료합니다. PC/모바일은 조회 기준이며 기본 입찰가를 변경하므로 양쪽 기기에 영향을 줄 수 있습니다.

VPS `.env.worker`에 `DATABASE_URL`과 **Vercel에서 사용하는 원래 APP_PASSWORD**를 설정합니다. 별도 로그인용 `LOGIN_PASSWORD`와 구분하세요. 저장한 네이버 API 정보를 복호화하는 키이므로 APP_PASSWORD를 새로 생성하면 안 됩니다. 파일 권한은 `chmod 600 .env.worker`로 제한합니다. 기존 DB 테이블을 사용하므로 추가 마이그레이션은 없습니다.

```sh
cp deploy/olbarun-bid-worker.service /etc/systemd/system/olbarun-bid-worker.service
systemctl daemon-reload
systemctl enable --now olbarun-bid-worker
systemctl status olbarun-bid-worker --no-pager
```

관리 화면에서 소수 키워드를 선택하고 목표/최대 입찰가를 저장한 뒤 자동입찰 실행을 누릅니다. 진행 상태, 순위와 실제 적용 이력은 5초마다 갱신합니다. 서버에 서비스가 없으면 실행을 거절합니다. 중지는 진행 중인 조회/요청 완료 후 다음 증액을 막습니다. 설정 변경·수동 적용·재동기화는 자동입찰 중지 완료 후 가능합니다.

Postgres 세션 advisory lock으로 중복 작업기를 막습니다. 프로세스 재시작은 진행 작업을 중단 상태로 만들며 기존 작업이나 불확실한 PUT을 자동 재시도하지 않습니다. 변경 전 시도 기록과 변경 후 검증/이력을 저장합니다. 광고 상태가 유효하지 않거나 실행 중 저장 설정이 바뀌면 작업을 중지합니다. 실패 시 네이버 관리자에서 현재 입찰가를 확인하고 동기화 후 다시 실행하세요.

로컬 테스트는 큐 설정 검증·그룹 입찰 상속·순위 최신성·목표/상한·중지·통신 오류 처리 규칙을 검증합니다. 실제 VPS의 첫 API 증액은 별도 운영 검증이 필요합니다.

읽기 전용 입찰 점검: `node --env-file=.env.worker scripts/bid-diagnose.mjs "남구철거"`. 저장 입찰가와 네이버의 유효 입찰가(그룹 상속 포함), 키워드/그룹 노출 가능 상태를 조회합니다. API 비밀키와 DB 연결 문자열은 출력하지 않습니다. 작업 실패 화면에는 키워드, 실패 단계, 검증 오류 또는 HTTP 상태를 표시합니다.

네이버 실제 유효 입찰가가 설정한 상한 이상이면 해당 키워드는 금액을 유지하고 다음 키워드로 넘어갑니다. 오래된 저장 금액과 다르더라도 상한 초과만으로 전체 작업을 실패시키지 않습니다. 화면의 현재 입찰가는 실제 금액으로 갱신하고 목표/최대 설정은 유지합니다. 불확실한 변경 결과는 계속 중지합니다.

저장 금액과 실제 금액이 달라도 상한 미만이면 직전에 조회한 네이버 유효 입찰가를 기준으로 10원 증액합니다. 목표와 상한은 유지하며 실제 변경 전후 금액을 이력에 기록합니다.

순위 조회는 통합검색에서 광고를 확인한 경우 해당 순위를 우선합니다. 통합검색 목록에 없으면 같은 기기의 광고 더보기를 조회하며, 화면에 `18위 · 더보기 기준`처럼 출처를 표시합니다. 더보기 순위는 통합검색 노출 순위와 별개의 관측값입니다. PC는 최대 4페이지를 조회하며 페이지의 전체 순위 메타데이터를 검증합니다. 모바일은 해당 검색 결과의 모바일 더보기 링크만 사용합니다. 광고 링크를 클릭하지 않습니다. 확인 불가·중복 광고·기기 불일치에는 증액하지 않으며, 더보기로 증액할 때 광고 ID가 해당 네이버 광고그룹에 속하는지도 검증합니다.

읽기 전용 확인: `node scripts/rank-check.mjs "사하구철거" lastwar.co.kr PC`. `source`, `rank`, `moreRank`, `adId`를 확인하세요. VPS 작업기는 코드 업데이트 후 서비스 재시작이 필요하며, 재시작만으로 기존 자동입찰 작업을 재개하지 않습니다.

목표 유지 자동 절감 기능: 새 실행 요청은 `strategy: cost`로 생성합니다. 목표 밖은 +10원, 목표 이내의 서로 다른 새 조회가 3회 쌓이면 약 10%(최대 100원) 감액을 시험합니다. 반영시간 이후의 동일 기기·동일 조회영역 순위가 목표 밖이면 직전 유지 금액으로 복구합니다. 복구 후 30분 동안 감액을 쉬면서 감시하며, 실패 경계가 있으면 10원 단위로 범위를 좁힙니다. 설정한 최소·최대 금액을 지킵니다. 감액 중 일시적인 순위 하락이 가능하며 유지 금액은 관측값입니다.

목표 도달 후에도 전체 순위를 계속 조회합니다. 키워드별 상태와 변경 시각을 DB에 저장하므로 재실행 시 불확실한 입찰 변경을 반복하지 않습니다. 실제 금액이 마지막 변경 금액과 다르면 금액을 유지하고 확인을 요청합니다. 네이버에서 확인 후 작업을 중지하고 계정 동기화를 하면 확인된 실제 금액을 새 기준으로 삼습니다. 재시작은 실행 작업을 중단하며 사용자 실행 버튼으로 새 작업을 시작해야 합니다. 화면에 유지 확인 금액·감액 시험·복구 상태를 표시하고 이력에는 자동감액/순위복구를 구분합니다.

웹 배포 후 VPS도 `git pull --ff-only`, `npm ci`, `systemctl restart olbarun-bid-worker`로 업데이트해야 합니다. 새 절감 작업은 최신 작업기의 준비 상태가 확인되어야 실행됩니다. 이전에 실행한 증액 작업은 중지하고 새로 실행하세요. 로컬 규칙 검증은 실제 광고비 절감이나 특정 순위 유지를 보장하지 않습니다.

광고그룹 선택: 관리 화면은 기본으로 `파워링크#1_광고그룹#1`을 선택하며 해당 그룹의 키워드와 광고 URL만 표시합니다. 다른 그룹으로 전환할 수 있습니다. 선택·일괄 목표/상한 변경·평균 입찰 조회·CSV·자동입찰은 선택한 그룹에 한정됩니다. 서버도 자동입찰 요청에 다른 그룹의 키워드가 섞이면 거절합니다. 그룹을 전환해도 이미 서버에서 실행 중인 작업은 그대로 유지되므로, 실행 대상을 바꾸려면 기존 작업을 중지한 뒤 새 그룹에서 실행하세요.

최저가 1~5위 모드: 상단 ON/OFF 버튼은 하나만 켤 수 있습니다. ON인 순위와 선택 키워드의 목표 순위를 같게 설정해야 실행됩니다. 같은 기기·조회영역에서 해당 순위가 서로 다른 최신 조회로 5회 연속 확인되면 키워드의 가감액 단위(10~100원, 10원 단위)만큼 한 번 감액합니다. 감액 후 반영 확인과 목표 이탈 복구는 유지합니다. 모두 OFF이면 감액 없이 목표 밖 +10원 증액만 실행합니다. 모드 변경은 새 실행 요청부터 반영되며 개인 도구에 사용기간 제한은 없습니다. VPS의 최신 최저가 모드 준비 상태가 확인되어야 새 요청을 실행합니다.

순위 조회는 키워드별 조회 시작 간격을 최소 15초로 유지합니다. 조회·저장에 사용된 시간을 포함하며 15초를 넘긴 조회 뒤에는 추가로 15초를 쉬지 않습니다. 동시 조회 없이 순차 처리하고 입찰 반영 대기 시간은 별도로 유지합니다.

자동입찰은 회차 끝의 일괄 반영 대기 대신, 각 키워드의 마지막 변경 시각부터 설정된 반영 시간이 지난 뒤 조회합니다. 조회·다른 키워드 처리에 이미 사용한 시간을 차감합니다. 변경이 없는 감시 회차의 재조회 간격은 유지합니다.

검색 HTTP 403 발생 시 자동입찰 작업은 전체 조회 및 입찰을 멈추고 10분 후 동일 키워드를 한 번 재확인합니다. 계속 거부되면 작업을 종료하며, 재실행도 최소 10분 제한됩니다. 이는 접근 거부 해제를 보장하지 않습니다.

모바일 더보기는 같은 검색어의 실제 다음 페이지 링크를 최대 4페이지까지 추적합니다. 앞 페이지 광고 목록과 순위 메타데이터를 검증한 뒤 누적 목록 위치를 계산하며, 누락·중복·403은 확정 순위로 처리하지 않습니다.

## 광고그룹별 동시 운영

캠페인 → 광고그룹을 선택합니다. 이름이 같아도 `nccAdgroupId`로 분리합니다. 키워드가 없는 그룹도 동기화된 목록에 표시됩니다. 새로운 그룹은 실제 광고 사이트 URL을 입력하고 설정을 저장하세요. 기존 키워드의 목표·상한·선택은 동기화 시 보존됩니다.

각 그룹에서 기기, 목표, 상한, 대기시간을 설정하고 실행합니다. 작업은 `auto-job:<groupId>`에 따로 저장됩니다. 그룹별 전체 조회 → 관리 회차는 독립적으로 진행되며, 하나의 FIFO 대기열에서 검색과 입찰 요청을 순차 처리합니다. 검색 시작 간격은 전체 그룹을 합쳐 최소 15초입니다. 반영 대기 중 다른 그룹을 처리할 수 있습니다. 403 휴식은 전체 검색에 적용되며 휴식 중 입찰도 유지합니다. 같은 키워드를 PC/모바일 두 작업에 중복 등록할 수 없습니다.

다른 그룹이 실행 중이어도 중지된 그룹의 설정을 저장할 수 있습니다. 동기화·계정 변경·수동 입찰은 모든 그룹을 중지한 뒤 수행합니다. 작업기 재시작은 기존 실행 작업을 중단 처리하므로 그룹별로 다시 실행해야 합니다. 추가 서버는 필요하지 않습니다.

업데이트 순서: UI에서 실행 중인 그룹 중지 → VPS `systemctl stop olbarun-bid-worker` → `git pull --ff-only` → `systemctl start olbarun-bid-worker` → 화면에서 실제 키워드 동기화 → 각 그룹 설정 및 실행. 수동 rank-worker는 자동입찰 서비스와 같은 잠금을 사용하여 동시 수집하지 않습니다.

## 중지 후 재실행

중지 완료 후 실행 버튼을 누르면 `처음부터 다시 하기` / `이어서 하기`를 선택합니다. 처음부터는 현재 입찰가를 유지하면서 선택한 전체 키워드를 다시 조회합니다. 이어서는 같은 그룹·기기·키워드 순서·설정으로 중지한 회차의 남은 조회/입찰 판단부터 처리합니다. 완료한 입찰 판단은 반복하지 않습니다. 순위가 60초 이상 지나면 다시 조회하며 반영 대기는 그대로 지킵니다. 작업당 체크포인트를 저장하고 중지 요청 중에도 진행 정보 저장을 마칩니다. 결과가 확정되지 않은 입찰 요청이나 변경된 설정에서는 이어서 실행을 거부합니다. 서버 재시작/오류 작업은 자동 재개하지 않습니다. 이전 버전에서 만든 작업에는 이어서 진행할 체크포인트가 없습니다.


## 단계별 증액과 우선순위 작업기 (adaptive-300-v1)

- 목표보다 4순위 이상 뒤이거나 더보기에서 확인된 광고: 300원 증액.
- 목표보다 1~3순위 뒤: 50원 증액. 남은 상한 여유가 작으면 최대 입찰가까지만 적용.
- 목표 이내 증액 중단. 설정한 감액 기준 순위 2회 확인 후 10원 감액, 이탈 시 감액 전 금액 복구.
- 순위 미확인·오류·오래된 조회는 입찰가 유지.
- 키워드 조회 직후 판단. 미달·감액 확인 작업은 반영 대기 후 우선 배정하며, 준비된 일반 작업이 있으면 우선 작업 최대 3개마다 일반 작업 1개를 배정.
- 목표 도달 키워드는 최소 10분, 미확인은 최소 5분 뒤 재조회. 미달 키워드도 전체 대기열과 전역 15초 조회 간격 때문에 예정 시각보다 늦어질 수 있음.
- 체크포인트 v2에 대기열 저장. 미확정 네이버 변경 요청이 있으면 재실행/복구를 자동 반복하지 않음.
- 웹 배포만으로 VPS 동작은 바뀌지 않음. 모든 그룹 중지 후 VPS git pull 및 작업기 재시작, 새로고침 후 처음부터 실행 필요. 새 웹은 이전 작업기에서 신규 실행을 차단.


## 월~토 예약 운영 (KST)

- 네이버 광고 자체의 노출 일정은 광고주센터에서 월~토 05:00~20:00으로 설정. 이 프로그램은 광고 ON/OFF를 변경하지 않음.
- 그룹에서 실행을 한 번 누르면 작업기는 월~토 05:30~20:00에 입찰하고, 나머지 시간에는 예약 대기. 일요일은 실행하지 않음.
- 20:00부터 새 검색/입찰을 시작하지 않음. 경계 전에 발송된 네이버 요청은 이후 완료될 수 있음.
- 한국 날짜별·그룹별 완전 처리 회차를 기록. 1~2회차는 목표 밖 우선으로 키워드를 1번씩 확인하며 새 감액을 보류, 기존 감액 복구는 허용. 3회차부터 기존 우선순위·감액 처리.
- 매일 새 운영일에는 1회차부터 시작. 수동 중지한 그룹은 다음 날 자동 실행하지 않으며 다시 실행해야 예약이 유지됨.
- VPS 서비스 중단·재시작·불확실한 요청 오류 후에는 기존 복구 정책에 따라 수동 재실행 필요.

## 부산 등 지역 제한 광고그룹 안전 운영 (1단계)

현재 Playwright 순위 조회는 VPS 검색 환경 기준이며 부산 위치를 인증하지 않습니다. 부산 전용 광고그룹의 검색 순위로 입찰가를 변경하면 잘못된 증액/감액이 발생할 수 있습니다.

VPS의 `.env.worker`에 네이버 광고그룹 ID를 쉼표로 구분해 지정하세요. 이름이나 키워드가 아닌 **실제 nccAdgroupId**입니다.

```dotenv
REGIONAL_ADGROUP_IDS=YOUR_BUSAN_ADGROUP_ID
```

기본 보호 대상 광고그룹: `grp-a001-01-000000074708929` (사용자가 부산 지역 제한 그룹으로 지정). 이 그룹은 `REGIONAL_ADGROUP_IDS` 설정이 없어도 보호됩니다. 다른 지역 제한 광고그룹은 환경변수에 추가하세요.

설정 후 서비스를 재시작하면 해당 그룹의 신규 자동입찰 요청은 `REGION_UNVERIFIED`로 종료되고 입찰가는 유지됩니다. 기존 실행 작업은 서비스 재시작 시 중단됩니다. 이 기능은 부산 순위를 만들어 내는 기능이 아니라 **잘못된 지역 순위에 따른 입찰 변경을 막는 임시 보호 장치**입니다. 정확한 지역 순위 수집 및 지역 검증이 구현·실측되기 전에는 이 차단을 해제하지 마세요. 기본 보호 대상 이외의 그룹은 `REGIONAL_ADGROUP_IDS`가 비어 있으면 기존 동작과 동일합니다.
